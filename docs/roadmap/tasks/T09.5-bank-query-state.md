# T09.5: Bank server state in TanStack Query

**Phase:** 1 · **Depends on:** T09 · **Size:** M

## Goal

Keep Zustand for client-only state. Move the bullet bank — data that lives in Postgres — into TanStack Query so `/bank` and the builder share one cache.

## Context

Today the server loads the bank (`loadBankForUser`) and `BuilderScreen` copies it into Zustand once (`hydrate`). The content slice then holds `bank` next to session state (`selections`, tailor matches). Style and tailor slices are client state too. `@tanstack/react-query` is not installed. T09 adds the editor that writes the bank (autosave, optimistic updates, `updated_at`). Those writes should not grow a second copy of the bank inside Zustand. T10 and later bank writes should use the same cache.

## Scope

- Add TanStack Query. One query for the signed-in user's live bank (`ResumeData`). Server prefetch plus hydrate so the first paint still has data.
- Bank writes from the T09 editor and JSON import/export go through mutations. Optimistic cache update, then reconcile with the server. Conflict handling stays the T09 `updated_at` check.
- Builder reads the bank from the query. A bank edit on `/bank` shows up in the builder without a full reload, and the reverse.
- Zustand keeps client state only: selections, style, tailor session (JD match, bullet/highlight matches), and local UI (pane, toasts). Drop `bank` from the store.
- When the cached bank changes (import, delete a slot the selection still points at), rebuild or prune selections that reference missing ids. Do not persist selections (T13).

## Out of scope

PDF import (T10), saved resume versions (T13), persisted style presets (T11), embeddings (T24). No schema change.

## Decisions (resolve in Plan mode)

- Granularity of writes: keep whole-bank replace (`replaceBankForUser`) behind one mutation, or split per-entity mutations now that the editor exists.
- Builder `personalInfo`: session override (stays in Zustand, as today) vs. always the bank document from the query.
- How a selection that points at a deleted slot/version is repaired.

## Acceptance criteria

- Zustand no longer stores the bank document.
- An edit saved on `/bank` is visible in the builder, and a reload shows the saved bank, not a stale client copy.
- Selections, style, and tailor results still behave as session state across that update.
- JSON import updates the same query cache the editor and builder read.
